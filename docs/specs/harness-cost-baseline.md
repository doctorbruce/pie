# Harness 本地成本基线

状态：已完成（2026-11-01）。

## 问题与目标

控制回归通过不能说明长历史、多会话的成本。本次提供可重复、无需模型凭据的本地测量入口，报告明确工作负载下的读取耗时、传输体积、RSS 和磁盘占用，供后续资源决策比较。

## 范围与实现

- `examples/harness-baseline.ts` 使用独立临时目录和 faux，运行真实 Local/SQLite/Runtime；不继承模型环境、不访问真实 Provider。
- 对比 100 与 10000 条历史的 50 条分页读取；另测显式完整快照，避免把有意的全量操作混入普通读取成本。
- 并发执行 16 个独立会话，测量执行基线与直接作业查询的响应体积，并报告启动、重启、RSS 和数据库磁盘占用。
- 输出 JSON；检查消息数、结算和轻量响应的结构正确性，不设置依赖机器速度的硬性耗时门槛。不增加通用遥测平台、真实 coding 任务评测或 Cloud 实现。
- RSS 是整个工作负载后的进程采样，包含调用者仍持有的显式完整快照和依赖开销，不代表闲置内存、峰值或分页常驻成本；只有对同版本、同环境采样才有可比性。

## 验收

运行 `node --expose-gc --conditions=source examples/harness-baseline.ts`，确认本地断言通过、输出完整且临时目录已删除；执行 `npm run check`。测量值仅作同环境基线，不宣称 coding 成功率或稳定性能 SLA。

## 实施记录

- `examples/harness-baseline.ts` 已实现上述工作负载、JSON 输出和行为断言；正常与失败路径均删除脚本拥有的临时目录，不继承提供商凭据。
- `node --expose-gc --conditions=source examples/harness-baseline.ts` 通过（Linux，Node v24.22.1）。100/10000 条历史的 50 条分页分别为 61963/62367 字节，中位耗时约 0.94/4.70 ms；显式完整快照 12236652 字节，读取约 161 ms。分页体积有界，不据此承诺耗时与历史长度无关。
- 16 会话 faux 提交与结算约 165 ms；18 会话轻量执行基线为 8116 字节，空作业观察为 114 字节；重启约 4.5 ms。整个负载后 RSS 约 555 MiB，临时数据目录约 14.7 MiB；包含调用者持有的完整快照，不是闲置内存测量。
- `npm run check` 通过（只读 Biome 443 文件、TypeScript、模型数据）。本脚本无未验证项；整体 Runtime/Server 验收与提交由本轮升级统一记录。

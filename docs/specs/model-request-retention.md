# 模型请求记录的资源生命周期

状态：已完成（2026-11-01）。

## 问题与目标

Local 默认保存完整模型 payload，却没有容量、保留期和会话删除联动。长 coding 会话重复保存上下文会持续增加磁盘占用；关闭记录也不能破坏既有 payload hook。

## 范围与实现

- 保留默认记录，增加显式开关、宿主总字节/条数、保留期和单条上限；超过单条/总容量的请求跳过记录，不保存截断 payload，模型调用继续。
- 在启动及写入时清理过期记录，使用单写队列和首次扫描后的索引维护宿主跨会话预算；恢复清理遗留临时文件。静默宿主不承诺实时 TTL 删除。
- 默认保留 7 天、100 MiB / 1000 条，单条最多 16 MiB；支持环境变量覆盖，非法配置尽早报错。
- 在 Local 的 Store 删除适配中清理相应会话文件，覆盖 Runtime 逐项删除的子会话；记录故障只警告，不把已成功的数据库删除误报为失败。
- 不引入依赖、管理平台或 Cloud/Astron 改造；共享 Runtime 记录器注入契约不变。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PI_MODEL_REQUEST_RECORDING` | `1` | 仅接受 `0/1`；`0` 停止新记录，仍执行旧记录的启动维护和会话删除清理 |
| `PI_MODEL_REQUEST_MAX_BYTES` | `104857600` | 当前数据目录受管 JSON 记录的合计字节上限 |
| `PI_MODEL_REQUEST_MAX_FILES` | `1000` | 当前数据目录受管记录的总条数上限 |
| `PI_MODEL_REQUEST_MAX_AGE_MS` | `604800000` | 保留时间，按记录创建时间计算 |
| `PI_MODEL_REQUEST_MAX_RECORD_BYTES` | `16777216` | 单条 JSON 上限，实际取此值与总字节上限的较小值 |

数值配置均为正安全整数。预算不统计非受管文件、目录元数据或用户另存的副本。过期与最旧淘汰在启动维护及有效记录写入时触发，不承诺静默宿主实时 TTL。超限整条跳过；序列化和 IO 故障只发不含 payload 的一次警告，模型及原 hook replacement 不受影响。磁盘故障可能导致数据继续保留，清理不是安全擦除保证。

同一数据目录由一个 Local 宿主的 SQLite 锁独占；取得锁后才懒初始化记录索引。Store 关闭时先关闭记录器并排空写入，再释放锁，迟到 hook 不再写文件。根目录和会话目录符号链接不会被跟随；这不提供针对恶意同账户并发改目录的沙箱隔离。

## 验收

先复现缺少关闭/容量/过期/删除策略的回归，再运行相关 Node 测试与 `npm run check`。覆盖并发跨会话预算、重启维护、完整 hook、超限无截断及删除后代；不使用真实模型。

## 实施记录

- `packages/local/src/model-requests.ts`：配置校验、有界单写索引、启动/写入治理、原子临时文件恢复、会话删除、关闭失效令牌及符号链接边界。
- `packages/local/src/agent.ts` / `runtime.ts`：复用内置记录器实例；锁后维护，所有实际删除（含冷子会话）联动清理，先关闭记录器再关闭 Store。自定义记录器注入仍由宿主管理。

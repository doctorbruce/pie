# Pie 远端统一 Loop 演进

状态：草案，方向规划，尚未开始实现。更新日期：2026-10-14。

## 问题与目标

Astron + Pie 不应长期绑定为“一套 Agent 对应一台用户 VM”。目标是让 Pie 统一推进任务，按需把工具动作交给本机或云端执行环境；纯聊天和可信业务 API 不必创建用户执行 VM。

同一份 Agent 内核支持本地与云端部署，不维护两套 Loop。统一 Loop 指共享服务能力，不是所有用户共用一个 Agent 上下文。

## 职责与边界

```text
桌面 / Web / IM / 客户系统
  → Astron 产品服务：身份、权限、助手配置、市场资产、知识与记忆
  → Pie：Session、Turn、上下文、模型调用、Subagent、Loop
  → 工具执行路由：可信业务 API / 本机 Worker / 云端 Worker
  → 执行环境：浏览器、APA、文件与脚本；按需使用 VM 或容器
```

- Worker 是执行具体动作的环境，不是另一个 Agent；Subagent 的决策仍由 Pie 管理。
- 浏览器、桌面、Excel、APA 等执行能力继续由 Astron Engine 或执行端承载，不搬进共享 Loop 进程。
- 一个运行中的会话只有一个 Loop 所有者；本地与云端不能同时推进同一任务。

## 优先演进方向

### 1. 工具执行与 Loop 解耦

- 保留现有工具参数、结果、取消及过程更新契约，在服务层支持本地执行和远端执行两种装配方式。
- Loop 不感知网络协议和沙箱供应商；先复用现有 Astron 执行能力，打通真实浏览器与 APA 的远端调用。

### 2. 配置与会话有明确归属

- Assistant runtime、Session、工具权限和凭据按租户及所属应用隔离，配置更新只影响自己的作用域。
- 宿主注册不得覆盖其他宿主的配置；执行目标、路由与凭据按会话解析，不依赖共享进程的一套全局环境变量。

### 3. Skill / APA 资产可跨环境部署

- 区分给 Loop 的技能指引与给 Worker 的脚本、依赖和资源；保留共用资产，不重复建设市场体系。
- 执行包声明版本、操作系统和运行依赖；附件、工作区及产物使用可解析的引用，不直接依赖客户端绝对路径。
- Windows、Office、浏览器登录态等需求按能力匹配执行端，不默认 Linux 沙箱能替代所有 APA 环境。

### 4. 任务执行可追踪、可恢复

- 为工具执行保留稳定标识、执行端归属和持久结果，区分执行中、成功、失败与结果未知。
- 长任务、用户确认和设备离线支持持久等待；明确取消、超时、重连和服务重启后的处理方式。
- 有副作用的动作不因网络异常盲目重试；结果未知时先核对，再决定继续、重试或交给用户处理。

### 5. 共享服务的安全与扩容

- 对外开放前具备身份认证、租户授权、Worker 身份、凭据隔离与资源配额；不可信脚本和插件不得在共享 Loop 进程执行。
- 后续按实际规模补齐会话单一所有者、节点接管、事件续读及历史按需加载，避免多实例重复推进任务。
- 历史存储工作沿用 [历史存储 SPEC](history-storage.md)，不另建一套；不提前绑定数据库、消息队列或持久执行框架。

## 推进顺序与验收方向

| 阶段 | 范围 | 验收方向 |
| --- | --- | --- |
| 第一阶段：验证解耦 | 受控单租户 Pie 服务 + 一个远端 Astron Worker，先复用现有 VM | 纯聊天不创建执行 VM；同一个 Turn 完成远端真实浏览器操作、APA 执行和结果回传；本地模式仍可用 |
| 第二阶段：云端可交付 | 配置与数据隔离、资产部署、执行记录、确认与取消 | 两个租户不串配置或数据；断连后可查明执行结果；高风险动作不因重试重复执行 |
| 第三阶段：规模化与多设备 | 多 Pie 实例、按需执行资源、本地设备 Worker | 节点接管不双执行；设备离线可等待；云端与本地共享工具契约 |

## 本次不做

- 不实现上述能力，不展开接口字段、数据库表或调度算法。
- 不重写 Agent Loop，不把整套桌面 UI 搬到云端，不一次性拆成大量微服务。
- 不预先选定沙箱供应商；先验证执行解耦，再根据真实工作负载选择 VM、容器或 MicroVM。

# 精确重复工具调用检测

状态：已完成

## 问题与目标

模型可能连续使用相同参数调用同一工具。给模型一个轻量提醒，让它检查继续调用的必要性；不将重复调用直接判为任务失败或完成。

## 范围与不做的事

- 同一用户输入后的工具调用序列中，连续三次及以上同工具、同 JSON 参数时，在工具最终结果中追加提醒。跨模型轮次生效，也覆盖同一轮的多个调用。
- 对象键顺序不影响相等判断；数组顺序、值和工具名变化会打断连续计数。新用户输入（包括运行中的补充输入）重置边界。
- 提醒保留原始结果、错误标志、结构化详情及其他 hook 的覆盖结果。明确允许有理由的重复查询或轮询，不阻止执行、不要求用户确认。
- 不加入步数限制、语义相似检测、结果新颖度判断、额外模型请求、前端或协议改动，不修改基础 Agent loop 或 MCP 行为。

## 实现思路

- 在共享 Runtime 的 `afterToolCall` 接入检测，供本地与嵌入宿主共同使用。
- 按消息中的调用顺序向前检查最近三次请求，而非按并行工具完成顺序计数；不维护跨会话状态或保留额外历史引用。
- 提醒随最终工具结果保存并传给下一次模型请求；已发出的并行调用不撤回。历史压缩后只检查仍在工作窗口中的原始调用，不从摘要推断重复。
